# Responses to the red team's first review of the Explain spec

All 18 findings were accepted in substance. `SPEC.md` §20 maps each one to the sections that now handle it, and `DECISIONS.md` carries the owner-facing changes (D2, D3, D4, D5, D6, D8, and the new D13 and D14).

The lines below cover every part of a finding that was **rejected, or taken in a different form than proposed**, and why.

- **Finding 17, partly rejected ("bundle the current and the previous rule pack … so a rules release doesn't take Explain down").** Bundling the previous pack alone can't prevent the outage: Pages deploys the new rules the moment they merge to `main`, before anyone can deploy the backend, and the backend can't accept a version it hasn't been given. The spec still bundles both (it keeps pages loaded before a release working), and adds what actually closes the gap: `site/data/explain.json` lists the versions the live backend accepts, the button hides itself with a "catching up" note when the site's version isn't listed, and §13 sets the release order (merge, owner deploys, PM adds the version to the list). A rules release therefore hides the button for a while instead of producing failed requests; it doesn't avoid the pause altogether.
- **Finding 15, alternative taken (pin `job_workflow_ref` or edit BLUEPRINT §5).** The spec edits BLUEPRINT §5 instead of pinning the workflow. Pinning needs a REST call on a repository OIDC setting, which the owner can't do by clicking. GitHub documents the claim for reusable workflows. And every workflow file is already under `.github/`, a protected path the owner merges. §19 item 7 keeps the pin as a follow-up if AWS accepts a condition on that claim.
- **Finding 4, alternative taken (a parameter-only update, or the deploy role setting concurrency to 0).** The spec uses the parameter-only `update-stack --use-previous-template`. Giving the deploy role `lambda:PutFunctionConcurrency` and `DeleteFunctionConcurrency` would let it change the live service outside CloudFormation, and on a new account with a low concurrency quota the same call may be refused. The console Throttle stays as the no-GitHub emergency stop, and the setup sitting drills it.
- **Finding 2, one wildcard kept.** The two read-only settings calls the finding asks the function role to have (`GetModelInvocationLoggingConfiguration`, `GetAccountDataRetention`) act on the whole account and, as far as the API model shows, on no named resource, so they take `"Resource": "*"`. That need can't be avoided. It is read-only, and §19 item 1 re-checks the Service Authorization Reference for a resource type before the build.
- **Finding 7, different mechanism for "the same version check".** `site/data/moves.json` carries no version of its own, so the spec keeps the backend's copy honest with a CI test that it is byte-identical to the site's (as `sync_rules.py` does for the pack), plus the test the finding asked for (the name in the prompt equals the UI name).
- **Finding 18, check loosened slightly ("require `how` to contain a word from the marked span or the move's name").** Exact word matching would reject ordinary answers ("economists" against a marked "economist", "agreement" against "agrees"). Check 9 compares words of four or more letters by their first five letters. The prompt also now tells the model to point at the marked words, so the check should rarely bite on honest answers; the evaluation measures that.
- **Finding 12, the cap's `MaxValue` set to 25.** The finding asked for a maximum without naming one. Setting it at the approved $25 makes any higher cap a reviewed change that goes together with raising the budget in the setup stack, so the two can't drift apart. D4 tells the owner this.
- **Finding 14, tax left in the budget.** The finding noted that the budget counts tax by default, without asking for a change. The spec keeps that default on purpose: it makes the backstop fire slightly earlier, which is the safe direction, and says so.
- **Finding 3, one extension.** Besides `explain/`, the spec also protects `site/js/explain.js` and `site/data/explain.json`, because they decide what leaves the browser. It also records, and doesn't adopt, a private network for the function, which would make the "no text leaves the function" promise technical. The two VPC endpoints it needs cost roughly $15 a month, more than half the model cap (SPEC §2, §19 item 9).
